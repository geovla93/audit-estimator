On 2026-11-17, the exact npm registry metadata for the seven refreshed pins and the installed `oxlint-tsgolint` peer were queried with `pnpm view <package>@<version> version license engines peerDependencies scripts --json`. Versions, licenses, declared engines and peer requirements matched the frozen-installed manifests. Neither registry metadata nor installed manifests lists a `preinstall`, `install`, `postinstall` or `prepare` hook for these packages; published build, test and publish scripts are not install hooks. The exact records are [Slang 1.3.10](https://www.npmjs.com/package/@nomicfoundation/slang/v/1.3.10), [tsdown 0.23.4](https://www.npmjs.com/package/tsdown/v/0.23.4), [Oxlint 1.89.0](https://www.npmjs.com/package/oxlint/v/1.89.0), [oxlint-tsgolint 7.0.2004](https://www.npmjs.com/package/oxlint-tsgolint/v/7.0.2004), [Oxfmt 0.78.0](https://www.npmjs.com/package/oxfmt/v/0.78.0), [@types/node 25.9.9](https://www.npmjs.com/package/@types/node/v/25.9.9), [Zod 4.6.7](https://www.npmjs.com/package/zod/v/4.6.7) and [smol-toml 1.9.1](https://www.npmjs.com/package/smol-toml/v/1.9.1). Upstream release notes reviewed for the changed versions are [Slang 1.3.10](https://github.com/NomicFoundation/slang/releases/tag/v1.3.10), [tsdown 0.23.4](https://github.com/rolldown/tsdown/releases/tag/v0.23.4), [Oxlint 1.89.0](https://github.com/oxc-project/oxc/releases/tag/oxlint_v1.89.0), [Oxfmt 0.78.0](https://github.com/oxc-project/oxc/releases/tag/oxfmt_v0.78.0) and [smol-toml 1.9.1](https://github.com/squirrelchat/smol-toml/releases/tag/v1.9.1). The [Zod 4.6.7 release tag](https://github.com/colinhacks/zod/releases/tag/v4.6.7) has no descriptive release notes, and the `@types/node` release page has no per-version release note.

The [Slang 1.3.10 notes](https://github.com/NomicFoundation/slang/releases/tag/v1.3.10) add grammar support through Solidity `0.8.38` and include parser fixes. `LanguageFacts.allVersions()` in that installed package reports the available range as `0.4.11–0.8.38`; this is grammar availability, not full compiler compatibility. The supported Node runtime remains Node 24 even though `@types/node` is now from the Node 25 declaration line. The earlier bootstrap and package checks, including Commander 15.0.0 and Picomatch 4.0.7, remain dated observations; Commander is imported only by the local CLI shim and is not bundled into the library entry. Picomatch's documented literal matching options and smol-toml's unsafe-key rejection option are used behind bounded analyzer-owned adapters. `smol-toml` 1.9.1 is newer than the 1.7.1 fix for [CVE-2026-85730](https://github.com/advisories/GHSA-7w5x-hrqm-74c2), which affects versions through 1.7.0; metadata parsing uses the 1.9.1 `unsafeKeyBehaviour: 'throw'` option. No dependency lifecycle script has been allowlisted; pnpm 11 uses `allowBuilds` in the repository-root `pnpm-workspace.yaml` if installation proves a specific dependency script is required. Add only a reviewed required package there. See [the Slang compatibility spike](research/slang-spike.md) for parser behavior, the research-only leading-BOM view and range mapping, and remaining binding limits.
