# Roadmap

This roadmap separates implemented local behavior from ideas that need an owner decision or evidence. It does not promise dates or future compatibility.

## Current direction

- Keep local analysis bounded, deterministic and data-only.
- Improve the quality and traceability of measured parser, metric and relationship evidence while preserving explicit unavailable states.
- Make package contents, schemas, documentation commands and release evidence mechanically reviewable.
- Defer predictive performance claims until consented calibration establishes a suitable dataset and evaluation method.

## Deferred until evidence or approval exists

The order below records dependencies, not delivery commitments:

1. **Safe remote acquisition:** define a bounded, verifiable fetch and archive extraction boundary before considering Git or archive inputs.
2. **Explorer metadata:** only after acquisition exists, review remote source identity, trust, provenance, privacy and network-failure behavior.
3. **Optional compiler or Slither adapters:** only after an owner-approved execution policy addresses code execution, compiler acquisition, isolation and provenance. No target compiler or Slither command runs today.
4. **Richer dependency analysis:** exact caller-selected contract scope and content-matched reuse of reviewed reference declarations are implemented ([dependency reuse](dependency-reuse.md)) and need no compiler adapter. Still deferred, and only after adapters and dependency evidence have tested ownership, path and completeness contracts: automatic ancestor, helper or callee closure, reachability, function-level or fuzzy delta accounting for maintained forks, a human-reviewed baseline and diff workflow, version or binding verification, and security-advisory policy.
5. **Consented calibration:** define data permission, sampling, reviewer effort conventions, leakage controls, error metrics and independent evaluation before changing coefficients or making empirical claims.
6. **Pricing:** only with explicit currency, rate, hours-per-day and commercial-scope inputs. A nonbinding price scenario must remain separate from technical effort and cannot invent a universal rate.
7. **Hosted CI action:** only after stable JSON behavior and input/output boundaries are established and an owner approves the operational policy.

Do not introduce a plugin architecture before multiple real adapters exist. Relationship refinements such as dynamic dispatch or user-defined storage details also need parser evidence and a bounded testable contract.

**Release identity and policy:** owner approval is required for a license, security contact, fixture redistribution, repository identity and any public distribution. No registry publication, OIDC setup or hosted workflow verification is claimed by this local documentation task.

## Explicitly not promised

There is no planned vulnerability detector, security score, automatic audit conclusion, pricing engine, schedule guarantee, statistical confidence interval, remote explorer, archive or external analysis tool integration. Revisit a deferred idea only with a named owner, clear safety boundary, testable scope and evidence that justifies it.
