# ADR 004: Bounded source discovery and safe reader handoff

Status: accepted for the internal discovery layer.

## Context

Source selection affects the files that can be analyzed, their canonical IDs, and completeness. Discovery therefore treats project files as data, constrains every path to the captured project and selected target, bounds filesystem work and bytes, and records why each observed alias was selected, excluded, or assigned an ownership class. This ADR defines internal contracts for plans 008 and 013; it does not change domain schemas or the public library entry point.

## Internal contracts

`readProjectMetadata({ pathContext, budget })` reads only the root `foundry.toml` as bounded TOML data and checks a fixed set of root-local Hardhat marker names by path inspection. It never opens JavaScript or TypeScript configuration, package files, or scripts. Its result contains safe config hints, normalized `libs`/`test`/`script`/`out` paths, a validity bit, an explicit metadata observation, and sanitized diagnostics.

Resolve operator configuration once before metadata, without metadata hints, and construct the shared `DiscoveryBudget` from those effective operational limits. User config may validly raise trusted defaults up to the validated ceiling, so a defaults-only budget must not be used as an upper bound. Metadata may then be read with that budget: Foundry metadata supplies only scope, import, and Solidity hints, never analysis limits. Resolve the final config with the metadata hints and require its limits to equal the pre-metadata operational limits. `DiscoveryBudget.tightenLimits()` supports a later policy-driven reduction; it is monotonic, preserves all counters and the original start time, and can only shorten the deadline. It rejects widening limits, limits already exceeded by accumulated work, and a smaller per-file source cap after source bytes have been read because per-file historical consumption is not retained. `DiscoveryBudget.tightenDeadline()` accepts an absolute monotonic-clock time and can only shorten the current deadline without resetting its start. `discoverScope` calls `budget.assertLimitsMatch(config.analysis.limits)` before inspecting the target, so a caller cannot pair stricter traversal settings with a looser reader budget. All later readers and import processing must receive this same budget instance; do not reconstruct it or reset its counters after metadata or discovery.

`discoverScope(input)` returns `{ manifest, snapshots, diagnostics, observations, complete }`. Observations include the chosen root mode and provenance, unread candidates, pruned directories, test-directory presence, filesystem/glob/source/metadata counters, exact rule records, and per-alias lexical and physical paths with selection, exclusion, and ownership reasons. Scoped manifest entries reference the exact safe-read snapshot and its hash. The manifest is validated with `ScopeManifestSchema`; these internal observations are not additions to domain schemas.

`readSource({ pathContext, budget, identities, adapter? }, path)` is the shared bounded source reader for selected files and later context reads. It checks lexical and physical containment, hard-excluded path segments, project-relative name representability, descriptor/file identity, and file-version stability before and after reads. It opens without following the final symlink where supported, never retries with weaker flags, reads bounded chunks, validates UTF-8, hashes original bytes, and caches the snapshot in `IdentityRegistry`. A cached snapshot is stable for that physical identity and captured source version; it avoids a second byte charge. The registry freezes the representative path before publishing a snapshot. Later aliases can add ownership evidence but cannot rename the snapshot or its file ID.

`DiscoveryBudget` exposes monotonic counters and the effective immutable `limits`. It charges source, metadata and coverage-artifact bytes actually returned before propagating cancellation or deadline errors. It charges each returned directory entry before checking interruption, and glob matcher states before advancing. A source identity reservation counts once across discovery and later reads; failed selected reads remain recorded and make discovery incomplete. Directory enumeration uses `opendir` with a fixed buffer, deterministic per-directory Unicode code-point sorting, and bounded depth and entry work. The `maxFsEntries + 1` probe is charged and stops the traversal without claiming an unobserved remainder is complete.

`readCoverageFile({ pathContext, budget, adapter? }, path)` is the dedicated reader for the one optional, configured, root-local coverage artifact (plan 009). It shares the descriptor, no-follow, identity, version-recheck, bounded-chunk and close-on-error machinery of `readMetadataFile` but charges a separate `lcovBytes` counter against the effective `maxLcovBytes` (4 MiB default; schema ceiling 40 MiB), never `maxFileBytes`, `maxTotalSourceBytes` or `maxMetadataBytes`. Metadata keeps its 256 KiB cap. The counter lives on the same `DiscoveryBudget`, is monotonic, is never reset by repeated reads, and `tightenLimits()` rejects a `maxLcovBytes` below bytes already consumed. Returned bytes, including an over-limit probe, are charged before cancellation, deadline or limit errors propagate. Like other metadata, the artifact uses root-only containment: the selected Solidity target boundary is removed from the path context so a report beside a literal `.sol` target can be read, while source and context confinement are unchanged. Symlinks are always rejected (even when source symlinks are followed), directories and special files are blocked, `.git` stays hard-excluded, and no weaker-flag retry exists. The reader returns bytes only; LCOV parsing is a separate data-only module and never opens paths named inside the artifact.

After a later context read observes another alias, plan 008 calls `await reevaluateIdentityOwnership({ identities, identityKey, scope, metadataPaths, scopedFileIds, budget })`. This asynchronous helper reclassifies every lexical and physical path recorded for that frozen identity in budgeted batches, then returns its current ownership rule plus any previously scoped file ID invalidated by a newly observed conflict. If an ID is invalidated, the caller retains the existing snapshot/ID for referential stability, emits the ownership limitation, and marks the overall result incomplete pending an explicit override. It must not count the same file twice or silently retain its former first-party eligibility.

## Selection and ownership rules

| Input or observation                                     | Selection behavior                                                                                                                                                        | Safety and ownership behavior                                                                                                                           |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Directory target with no include patterns                | Intersect configured or conventional source roots with the physical target after validating roots under the project root.                                                 | The walker and reader enforce both project and target boundaries.                                                                                       |
| Directory target with include patterns                   | Includes replace root selection and are evaluated against root-relative paths.                                                                                            | Config excludes win; hard exclusions always apply; defaults and metadata test/script/output exclusions apply only while default exclusions are enabled. |
| Literal `.sol` file target                               | Select the literal file without applying include or source-root selection.                                                                                                | Evaluate lexical and physical exclusions, project/target containment, and ownership before reading.                                                     |
| Literal non-Solidity, blocked, missing, or unsafe target | Record an unreadable/blocked candidate and mark the result incomplete.                                                                                                    | Do not read or promote it.                                                                                                                              |
| Observed hardlink aliases                                | Group by safe physical identity before final classification; choose the smallest observed root-relative physical path by Unicode code point until the identity is frozen. | Freeze before publishing the first snapshot. Preserve alias-specific reasons.                                                                           |
| Conflicting alias ownership                              | Keep the identity unknown unless an explicit first-party override covers the conflicting dependency paths.                                                                | A plain excluded alias does not veto an independently eligible alias; known third-party omissions explain the promotion path.                           |

Configured roots and ownership roots are validated at project-root scope before intersecting the selected target. This preserves a valid ancestor root when the user targets a subtree, while a disjoint root produces a target mismatch. A symlink alias cannot bypass physical containment, target containment, `.git` exclusion, or ownership checks. Unseen hardlinks and pruned paths are not claimed as classified.

## Completeness, diagnostics, and limits

Unsafe paths and failed reads use fixed sanitized messages; native paths, source bytes, TOML parser details, and target-provided text do not enter diagnostics. Budget interruption propagates as a budget error instead of being rewritten as an unreadable path. Bounded selected read failures, relevant target failures, ownership ambiguity, traversal truncation, and metadata invalidity prevent a complete result. `LIMIT_EXCEEDED`, `PATH_BLOCKED`, `TARGET_UNREADABLE`, `SOURCE_CHANGED`, and `OWNERSHIP_UNKNOWN` remain within the existing diagnostic vocabulary; structured observations preserve the details needed by plan 013 to map omissions into bounded report limitations.

Plans 008 and 013 may read scope-excluded, otherwise safe Solidity sources as context through the same `readSource` adapter, `IdentityRegistry`, and `DiscoveryBudget`. Such reads consume unique-file and cumulative source-byte limits and reuse cached snapshots. Context inclusion does not change ownership, promote audit scope, or bypass hard exclusions, containment, or target policy. Any failed context read or exhausted budget remains visible to completeness/reporting.

The reader checks lexical components and resolved paths before opening, rechecks them immediately after opening and after reading, and verifies descriptor identity and version. These checks narrow race windows but Node does not expose an atomic open-beneath operation here, so a hostile concurrent filesystem mutation cannot be claimed impossible on every platform. `O_NOFOLLOW` and `O_NONBLOCK` are included when the runtime exposes them; an absent constant falls back to the flags available on that runtime. If a present flag is rejected by `open`, the read fails closed and does not retry with weaker flags. Inode/device identity is preferred; when those values are unavailable or unreliable, the safe physical project-relative path is the identity fallback, which cannot reliably coalesce hardlinks. FIFO and permission behavior depends on the host filesystem and effective user; tests capability-detect those platform conditions and report skips rather than treating unsupported host behavior as proof of safety. This implementation was run on Darwin arm64 only; other operating systems and filesystem implementations remain unverified.

## Consequences

Discovery is deterministic for the same observed filesystem and effective config, but completeness remains explicit when limits, races, unreadable entries, or platform behavior prevent full observation. New metadata ecosystems need a separate bounded data-only adapter and a reviewed interpretation contract. Parser isolation is not a filesystem sandbox. Future phases must retain this result and its observations rather than reducing the handoff to `ScopeManifest` alone.
